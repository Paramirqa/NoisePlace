Руководство разработчика

1. Требования

Для локальной разработки используются:

* Go — backend и бизнес-логика.
* Docker и Docker Compose — запуск приложения и PostgreSQL в контейнерах.
* PostgreSQL — база данных.
* golang-migrate — управление миграциями.
* sqlc — генерация Go-кода из SQL-запросов.

Убедись, что Docker Desktop запущен.

Проверить доступность инструментов:

go version
docker --version
docker compose version
sqlc version

2. Запуск проекта

Из корневой директории проекта выполни:

docker compose up -d --build

Команда собирает образы при необходимости и запускает сервисы в фоновом режиме.

Посмотреть состояние контейнеров:

docker compose ps

Посмотреть логи всех сервисов:

docker compose logs -f

Посмотреть логи конкретного сервиса:

docker compose logs -f app

Имя сервиса app приведено как пример. Проверь фактическое имя backend-сервиса в compose.yaml.

3. Пересборка backend

Если изменился только Go-код и нужно пересобрать backend, не пересоздавая базу данных:

docker compose up -d --build --no-deps <backend-service>

Замени <backend-service> фактическим именем backend-сервиса из compose.yaml.

Эта команда:

* пересобирает образ backend;
* пересоздаёт его контейнер при необходимости;
* не запускает зависимости автоматически благодаря --no-deps;
* не удаляет данные PostgreSQL.

Если приложение запускается через Dockerfile, изменения Go-кода попадут в контейнер после сборки нового образа.

4. Остановка контейнеров

Остановить сервисы, сохранив контейнеры:

docker compose stop

Запустить остановленные сервисы:

docker compose start

Остановить и удалить контейнеры и сеть проекта:

docker compose down

Важно: docker compose down не удаляет именованные volumes по умолчанию. Данные PostgreSQL обычно сохраняются в volume.

Не используй docker compose down -v, если не хочешь удалить volumes и потенциально потерять данные базы.

5. Работа с миграциями

Миграции находятся в директории:

db/migrations/

Применить миграции можно через настроенный сервис migrate:

docker compose run --rm migrate

Команда предполагает, что сервис migrate определён в compose.yaml и его конфигурация настроена.

При изменении схемы базы данных:

1. Создай новую миграцию.
2. Опиши изменения в *.up.sql.
3. Опиши обратные изменения в *.down.sql.
4. Примени миграцию.
5. Обнови sqlc-код.
6. Запусти тесты.

Не изменяй уже применённые миграции: для новых изменений создавай миграции со следующим номером.

6. Генерация sqlc

Исходные SQL-запросы хранятся в:

db/queries/

Конфигурация sqlc находится в:

sqlc.yaml

После изменения SQL-запросов или схемы базы данных выполни:

sqlc generate

Проверить конфигурацию:

sqlc compile

Сгенерированный код находится в:

internal/database/sqlc/

Не редактируй эти файлы вручную.

7. Тестирование

Запустить все тесты:

go test ./...

Запустить тесты с подробным выводом:

go test -v ./...

Проверить сборку всех пакетов:

go build ./...

После изменений рекомендуется выполнить:

gofmt -w .
go test ./...
go build ./...

gofmt -w . форматирует Go-файлы в текущем каталоге и его подкаталогах. Перед запуском проверь git diff, чтобы убедиться, что форматирование не затронет нежелательные изменения.

8. Проверка HTTP API

Проверка работоспособности приложения:

curl -i http://localhost:8080/healthz

Проверка готовности приложения и подключения к PostgreSQL:

curl -i http://localhost:8080/readyz

Эти команды предполагают, что backend доступен на порту 8080 хост-машины. Если в compose.yaml указан другой порт, используй его.

Ожидаемый ответ /healthz:

{
  "status": "ok"
}

9. Полезные команды Docker Compose

Посмотреть запущенные контейнеры:

docker compose ps

Посмотреть логи backend:

docker compose logs -f <backend-service>

Перезапустить backend без пересборки:

docker compose restart <backend-service>

Посмотреть используемые образы:

docker compose images

Проверить состояние контейнеров и опубликованные порты:

docker compose ps

12. Рекомендуемый рабочий процесс

При изменении Go-кода:

1. Внеси изменения.
2. Запусти go test ./....
3. Проверь сборку командой go build ./....
4. Пересобери backend-контейнер, если необходимо проверить изменения в Docker.

При изменении SQL-запросов:

1. Измени файл в db/queries/.
2. Выполни sqlc generate.
3. Запусти тесты.
4. Пересобери backend, если требуется проверить изменения в контейнере.

При изменении схемы базы данных:

1. Создай новую миграцию.
2. Примени её.
3. Выполни sqlc generate.
4. Запусти тесты.
5. Проверь работу API.
